20) scripts/training_loop.py:134
Q: `why p_ref is defined this way`
A: `p_ref` is the uniform reference distribution over buckets; it is used as baseline behavior and as the KL anchor for stability penalty.
Used in two places:

For the baseline run (when use_teacher=False): The teacher doesn't make decisions; instead, we sample uniformly from buckets using p_ref[:].

For stability penalty (in both runs): The teacher's learned distribution is penalized for deviating too much from p_ref. The stability penalty computes KL divergence between the teacher's action a_t and p_ref:
stability_penalty = compute_stability_penalty_kl(a_t, p_ref)
reward = validation_improvement - lambda_cost * compute_cost - alpha_stability * stability_penalty\

This encourages the teacher to stay somewhat close to uniform sampling, preventing it from collapsing to a single bucket.

---------- UNDERSTANDING THE TEACHER MORE ----------


Teacher looks at:
1. where we are in training,
2. how hard/easy each bucket currently seems,
3. whether each bucket is improving or not.

Then it outputs:
a probability distribution over buckets.

Example:
K = 3 buckets: easy, medium, hard

softmax(logits) = [0.20, 0.55, 0.25]

Meaning:
20% chance sample from easy
55% chance sample from medium
25% chance sample from hard


--------

Given:

a_t = [0.20, 0.55, 0.25]

easy   = 20%
medium = 55%
hard   = 25%

and suppose your training batch size is:

B = 8

Then for each of the 8 examples in the batch, you first sample a bucket using a_t.

Example sampled buckets:

Example 1 → medium
Example 2 → easy
Example 3 → medium
Example 4 → hard
Example 5 → medium
Example 6 → medium
Example 7 → hard
Example 8 → medium

So the batch may look like:

training_batch B_t = [
    one example from medium bucket,
    one example from easy bucket,
    one example from medium bucket,
    one example from hard bucket,
    one example from medium bucket,
    one example from medium bucket,
    one example from hard bucket,
    one example from medium bucket,
]

In counts:

easy:   1 example
medium: 5 examples
hard:   2 examples
total:  8 examples

This roughly matches [0.20, 0.55, 0.25], but it will not be exact every time because it is sampled randomly.

The teacher update confusion is important:

At each step t:
    teacher produces a_t
    student trains using batch sampled from a_t
    reward r_t is computed
    log_prob_t is stored

But teacher parameters φ are NOT updated yet.

After T steps:
    compute returns q_t
    compute advantages A_t
    update teacher once using all stored log_probs and rewards

So the teacher is acting during every step, but learning only after the episode ends.

########## VISUAL GRAND SCHEME ##########

Episode 1 starts
    t = 0: teacher gives a_0 → sample batch B_0 → train student → get reward r_0
    t = 1: teacher gives a_1 → sample batch B_1 → train student → get reward r_1
    t = 2: teacher gives a_2 → sample batch B_2 → train student → get reward r_2
    ...
    t = T-1: teacher gives a_T-1 → sample batch B_T-1 → train student → get reward r_T-1

Episode ends
    use all rewards + log_probs
    update teacher φ once

So the key idea is: Teacher actions affect the student immediately. Teacher parameters are updated later, after seeing whether those actions helped.



---- ---- ---- ---- CLARIFICATION ROLE OF TEACHER VS STUDENT in PERFORMANCE ---- ---- ---- ---- 


Totally valid confusion. The key is: the teacher is not learning how to answer the math question.

It is learning something much simpler:

Given how the student is doing right now,
which difficulty bucket should I train it on next?

The student LLM learns the complex token-level math behavior:

problem → reasoning tokens → final answer tokens

The teacher only learns the training schedule:

easy vs medium vs hard sampling

So the teacher is not saying:

“generate these exact correct tokens”

It is saying:

“at this point in training, give the student more medium questions”

A good analogy:

Student = person learning math
Teacher = tutor choosing the next worksheet

The tutor does not solve inside the student’s brain. The tutor just chooses whether the next worksheet should be easier, similar, or harder.

For example, suppose:

K = 3 buckets
easy, medium, hard

At step 0, the student is weak. The teacher may output:

[0.70, 0.25, 0.05]

meaning mostly easy questions.

After several updates, easy loss improves, but medium loss is still high. The teacher may output:

[0.20, 0.65, 0.15]

meaning now focus on medium.

Later, once medium improves, it may shift to:

[0.10, 0.35, 0.55]

meaning introduce more hard examples.

So what is being learned is not “math reasoning directly,” but:

Which training examples produce the best validation improvement?

That is why the reward is based on:

val_loss_before - val_loss_after

If sampling more medium questions improves validation loss, the teacher receives positive reward for that choice. If sampling hard questions too early makes training unstable or useless, the reward is small or negative.

In simple terms:

Student learns the answers.
Teacher learns the curriculum.

Your PoC is testing whether a learned curriculum can beat:

random sampling / uniform bucket sampling

not whether the teacher itself understands math.
